# xjtts — 设计文档（PLAN）

> macOS 原生 App：基于 llama.cpp `llama-tts` 的 Qwen3-TTS 声音克隆 / 纯文本合成工作站
> 版本：v1.3 · 2026-09-08 · 作者：Sutudio

## 1. 背景与目标

Qwen3-TTS-12Hz-1.7B（GGUF）已经可以在本地跑通 `llama-tts`，支持两种用法：

1. **零样本声音克隆**：给一段参考人声（wav/mp3），用那个声音读任意文本
2. **纯文本合成**：不给人声参考，直接出默认音色

命令行好用但不顺手：参数要背、日志要盯、文件散落、没有试听。
本 App 的目标：**把「写文本 → 选参考声 → 微调参数 → 生成 → 试听 → 保存」做成一个顺手、美观、符合直觉的桌面流程。**

非目标（v1 不做）：批量队列、流式播放、Web 服务、多模型切换 UI（模型路径可在设置里换，但一次只挂一个）。

## 2. 用户与核心场景

| 场景 | 用户动作 | App 必须做到 |
|---|---|---|
| 克隆自己的声音 | 拖入录音 + 粘贴文字 + 点生成 | 5 步内出音频 |
| 快速念一段文案 | 输入文字 + 点生成 | 无参考音频也能跑 |
| 调感觉 | 改 temp/top-k/seed 重新生成 | 参数改动即时生效，历史可回溯 |
| 找文件 | 试听完想存/打开文件夹 | 一键打开路径、另存为 |

## 3. 总体架构

```
┌───────────────────────────── App (SwiftUI) ─────────────────────────────┐
│  TabView                                                                │
│  ├─ 声音克隆   SynthesisTabView(mode: .clone)                          │
│  ├─ 纯文本合成 SynthesisTabView(mode: .plain)                          │
│  └─ 设置       SettingsView                                            │
│  底部常驻：LogConsole（流式日志 + 帧进度）                               │
└──────────────────────────────┬──────────────────────────────────────────┘
                               │ 调用
                     ┌─────────▼─────────┐
                     │     AppState      │  @MainActor ObservableObject
                     │  settings(持久化) │  · 生成状态机 idle/running/success/failed
                     │  状态机+历史+播放  │  · 单进程管理 Process
                     └─────────┬─────────┘
                               │ exec
                     ┌─────────▼─────────┐
                     │   llama-tts       │  一次性进程：stderr 流式解析
                     │ (~/llama.cpp)     │  "frames generated: N" → 进度
                     └───────────────────┘  "wrote <path>" + exit 0 → 成功
```

**关键决策**：

- **不内嵌推理引擎**：直接 `Process` 调 `llama-tts` 可执行文件。llama.cpp 是迭代最快的 C++ 项目，内嵌 libllama 只会绑定版本、丢失 Metal 优化；外部进程换来「llama.cpp 升级即 App 升级」。
- **一次性进程，不是常驻服务**：`llama-tts` 天然生成完就退出，App 按次拉起，省内存（1.7B 模型 + 编码器每次 ~1.5GB，用完即释）。
- **参数双份独立**：克隆/纯文本两个模式各自一份 `ModeParams`（temperature、top-k、top-p、min-p、seed、ctx-size…），互不污染，因为两种场景的最优参数往往不同。
- **路径全部可配置**：llama-tts 二进制、模型 GGUF、mmproj、输出目录，默认值直接填好本机已下载的文件，开箱即跑。

**交互原则（顺手）**：

- 生成按钮永远在视线内、永远可用（失败原因写进状态行，不弹窗打断）
- 参考音频三种给法：按钮选、拖进来、记住上次的
- 试听 = 播放/停止同键切换，全局同一时间只有一个音频在响
- 路径三件套无处不在：选路径的旁边必配「打开文件夹」
- 日志常驻底部，默认收起 110pt，展开 420pt，等宽字体、可选中复制

## 5. 核心数据流（一次生成）

```
校验：二进制可执行? 模型存在? (克隆)参考音频存在? 文本非空? 输出目录可建?
  ↓ 任何一项失败 → status=failed，原因拼进状态行（不弹窗）
组装参数（见 §6 映射表）
输出文件名：Qwen3TTS-{clone|plain}-{yyyyMMdd-HHmmss}.wav
Process(llama-tts, args)
  stderr readabilityHandler → 追加日志
  正则 "frames generated: (\d+)" → 进度帧数
terminationHandler:
  exit 0 且输出文件存在 → success：写历史(≤30条)、高亮结果卡
  否则 → failed：提示看日志
```

## 6. llama-tts 参数映射表

| App 字段 | CLI | 默认 | 说明 |
|---|---|---|---|
| llama-tts 路径 | （可执行文件） | `~/llama.cpp/llama-tts` | 需 2026-08 后构建 |
| 模型 | `-m` | NAS 上 Q8_0 | 必填 |
| 说话人编码器 | `--mmproj` | NAS 上 mmproj | 不存在则不传（纯文本可跑） |
| 文本 | `-p` | — | 必填，任意长度 |
| 语言 | `--tts-lang` | `zh` | zh/en/ja/ko/de/fr/es/it/pt/ru |
| 参考音频（仅克隆） | `--tts-speaker-file` | 记住上次 | wav/mp3/m4a/flac |
| 温度 | `--temp` | 0.80 | 0.1–2.0，越高越发散 |
| top-k | `--top-k` | 40 | 0=关闭 |
| top-p | `--top-p` | 0.95 | 1.0=关闭 |
| min-p | `--min-p` | 0.05 | 0=关闭 |
| 随机种子 | `--seed` | -1(随机) | 同种子可复现 |
| 上下文 | `--ctx-size` | 4096 | 默认 32K 白吃 3.5GB KV，别开大 |
| 最大帧数 | `-n` | -1(不限) | 防 runaway 重复 |
| 线程 | `-t` | 0(自动) | |

## 7. 错误处理

| 情况 | 表现 |
|---|---|
| 二进制/模型/参考音频缺失 | 状态行红字列全所有缺失项，一次修齐 |
| llama-tts 崩了（exit≠0） | failed + 「退出码 N，请看日志」，日志保留现场 |
| 用户点停止 | SIGTERM，状态行提示已停止 |
| 输出文件意外缺失 | 即使 exit 0 也判 failed |
| 历史音频被手动删了 | 播放时报「文件不存在」，不崩 |

## 12. v1.1 新增功能（2026-09-08）

### 12.1 需求

1. **麦克风现场录音做参考声**：克隆场景下不一定手头有现成录音文件，应该能直接
   「按下 → 说两句 → 松开（点停止）」就拿到一段参考音频
2. **拖拽即用**：现在只能点按钮选文件。语音文件应能直接拖进参考音频框、
   txt 文档应能直接拖进文本框，落定即用

### 12.2 设计

**麦克风录音**

```
SpeakerPanel 操作行 +「🎙 录音」
  点按 → 请求麦克风权限（首次）→ AVAudioRecorder 开始
        文件：{输出目录}/clone-ref-{yyyyMMdd-HHmmss}.wav
        格式：WAV 16-bit PCM 24kHz 单声道（llama.cpp 音频加载器原生支持，
              不用 m4a——llama.cpp 不保证能解 aac）
  录制中 UI：红点脉动 + 「录音中… X.Xs」+ 按钮变「停止」
  点停止 → recorder.stop() → 校验文件 >0 字节
          → 自动填入参考音频框（app.speakerFile = 该文件）
          → 可直接点「试听」核对刚才说的内容
  出错（无权限/无设备/文件为空）→ 面板内红字提示，不打断其它操作
```

决策：录到输出目录而不是临时目录——参考音频是可复用资产，
和「这是 App 的产物」性质相同，且用户能顺手在 Finder 里管理它。

**拖拽即用**

| 拖入目标 | 接受类型 | 行为 |
|---|---|---|
| 文本框区域（两种模式） | `.txt .md .rtf .text` | 覆盖 app.text，字数实时更新；非文本文件拖入不响应 |
| 参考音频框（克隆模式） | `.wav .mp3 .m4a .flac .aac` | 覆盖 speakerFile 并记忆；非音频文件拖入不响应 |

实现：SwiftUI `.dropDestination(for: URL.self)` 挂在两个面板的具体区域上
（v1.0 挂在整页上、命中范围不直观，v1.1 收窄到目标框内），
拖入高亮边框给出明确反馈。

### 12.4 音频目录 input/output 分离 + 品牌图标

- **input/output 分离**：录音参考声 → `~/Music/xjtts/input/`，生成结果 → `~/Music/xjtts/output/`，设置页两行独立可改
- **旧目录迁移**：启动时把旧单目录里的 `clone-ref-*.wav` 搬到 input/，并把 lastSpeakerFile 重映射到新位置
- **设置容错**：`Settings.fromLoose` 兼容缺 inputDir 的旧 settings.json
- **图标**：assets/icon.png（透明底蓝色 logo）→ build_app.sh 自动转 xjtts.icns 内嵌；App 更名 **xjtts**

### 12.5 v1.2 播放器与播放状态修复

- **播放器**：参考音频区加播放/暂停、时间轴拖动、音量调节、选中段落裁剪导出
- **播放状态真相源**：用 `player?.isPlaying == true`（`isActive`）做唯一来源，弃用自维护的 `isPaused` 标志
- **时间轴串扰**：参考时间轴仅当 `playingFile == speakerFile` 时跟随，否则归零
- **播完按钮卡死**：`AVAudioPlayerDelegate` 是 NSObject 协议，`@MainActor` AppState 不能直接 conform → 独立 `PlaybackDelegate` 类（持有 AppState 引用），`audioPlayerDidFinishPlaying` 回调 `stopPlayback()`

### 12.6 v1.3 音色/情感参数 + 生成后保温（本版）

> 用户诉求：每次生成拉起一次 llama-tts、跑完即退（已是默认行为）；设置页加"常驻内存"开关（默认关）；音色参数进纯文本模式；语调/语气/情感参数在克隆和纯文本都可调。

**关键实测结论（别猜，逐条验证过）**

| 点 | 实测结果 |
|---|---|
| `-sys` / `--instruct` / `--emotion` | 当前 llama-tts（2026-08 后）help 里**没有**这些独立参数 |
| 风格/情感通道 | **该模型没有「只改语气、不朗读」的独立指令通道**（`-sys` 实测 invalid argument；官方 PR #26254 只列 `--tts-lang`/`--tts-speaker-file` 两个参数）。自然语言拼进正文会被连同念出。真正控语气 = 克隆模式用对应语气的参考音频 |
| 纯文本 + `--tts-speaker-file` | 被接受并改音色 → 纯文本也能指定说话人 |
| 常驻 server binary | 无 `llama-tts-server`/stdin 多轮；one-shot 是唯一形态 |
| 慢的根因 | 模型加载实测 ~43s（冷加载），推理本身很快 |

**实现**

1. **语调/语气/情感（实验性）**：`ModeParams.instruct`，留空=只读正文；填了会拼进正文被一同念出。UI 标「实验性」+ 说明"该模型无静默指令通道，想纯净正文请留空；真正控语气用对应语气的参考音频"。克隆与纯文本共用
2. **音色进纯文本**：SpeakerPanel 加 `mode`，两模式都显示；纯文本标题"音色（可选，指定说话人）"；Engine 纯文本也传 `--tts-speaker-file`
3. **生成后保温**：设置页"性能"区块，Toggle（默认关）+ 时长 Slider（1-30 分钟）。开启后每次成功生成起一个后台 `cat 模型 > /dev/null` 循环进程（每 15s 读一遍），把页缓存 keep 热，N 分钟后自动停，App 退出 `deinit` 清理。选它而非进程内常驻：工程风险最小、不依赖 llama.cpp 库版本、效果等价（命中页缓存）

**关于"常驻内存"的取舍**

llama-tts 是 one-shot，没有常驻推理 server。三个方案里选了**生成后保温**（最稳）：
- 后台预热缓存：要自己实现保温循环，且首次仍要等一次
- 进程内常驻推理：要 dlopen libllama，当前无 server 接口，可能要从源码重编，工程量和风险都最大
- **生成后保温（已选）**：后台 keep 页缓存 N 分钟，期间再生成跳过冷加载，最省最稳

**测试计划**

1. 参数面板点"开心活泼"→ 生成 → 试听语气变化；点"严肃正式"对比
2. 纯文本模式选一个音色 → 生成 → 声音应是该音色
3. 设置页开"生成后保温模型" → 生成一次 → 看状态"保温中" → 立即再生成 → 加载应比首次快
4. 关掉开关 → 生成 → 无保温进程；App 退出后 `pgrep` 无残留 cat 进程
5. `swift build` 零 error
